# Subdivision v3 extras: check main first, build what's missing

The full subdivision spec (v3, 57 tests) is already in project files as
`subdivision-2026-11-03-62d8458.zip`. Main has subdivision and smooth
rendering, but the build log only records the v1 hand-off, so some v3 items
may be missing. **First run every test in that zip's ORACLES.json against
main**, then build only what fails.

| Item | What to check | Test IDs |
|---|---|---|
| SDV-04, SDV-09, SDV-10 | Modo's own Subdivision kind at levels 1–3 (one Catmull-Clark step, then biquadratic patches sampled L × L; level 3 cube = 218 points, not 386) | SDV-O-SUBD-* (not `-edgew`) |
| SDV-06 | Boundary Rule Crease / Smooth / Crease Edges on open meshes | SDV-O-PSUB-grid-L1-crease, -smooth, -creaseEdges |
| SDV-07 | Edge weights on Catmull-Clark: covered by BEHAVIOR-EDGE-WEIGHTS.md in this folder | SDV-O-PSUB-cube-*-edgew* |
| SDV-13 | Mesh mixing Face and smooth polygons: the smooth part is subdivided as if the Face polygons weren't there; shared edges become its open boundary; Face polygons keep their points (a gap can open, as in Modo) | SDV-O-MIX-psub5-face1-L1, SDV-O-MIX-subd5-face1-L1 |
| SDV-14 | Mesh mixing both smooth kinds (see below) | do **not** test against SDV-O-MIX-subd3-psub3-L1 |
| SDV-15 | Freeze keeps UV maps: new polygons get UVs from a straight linear split of each face's UVs | no oracle; check by hand: freeze a Cube-tool cube at level 1, each face's UV square should be split into an even 2 × 2 |

**SDV-14, Operandi choice.** Modo keeps a mixed Subdivision / Catmull-Clark
mesh connected but its rule is unknown. Operandi: treat every smooth polygon
in such a region as Catmull-Clark for that surface, so it stays connected
with no gaps. Show nothing special to the user. Revisit if anyone notices.

Also open and not to be guessed at yet: UV smoothing on larger UV islands,
Linear UVs, UV Boundary Rule, adaptive subdivision, multiresolution.
