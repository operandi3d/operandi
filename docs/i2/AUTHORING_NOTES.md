# Independent authoring provenance and observation rules

No candidate code was imported,executed or used to create expected geometry. This
phase ran only task-local Python standard-library writers and literal structural
checks. The original I1 geometry/ID/UV files were independently fixed before I1 and
accepted with their documented limits; FIXTURE_ORIGINS binds every such read file.

- author_expectations.py copies original full G0/G1/G2 and pair/second-stage oracles;
  applies literal tip-Z/degenerate-wall changes for declared displacements,zero return,
  sparse/equal-seam and begun B; maps only declared newly allocated numeric roles for
  branches; makes100 meaningful translated closed-prefix graphs from G0. Its wall
  owners/endpoints/corner ordinals are explicit lists,never a neighbor/donor search.
- author_controls.py adds literal cases,session/journal/counter/preset/rollback tables,
  exact negative/refusal/fault and scope/stale scenarios. It is a fixture writer,not
  an executable reference editor: it does not accept or simulate arbitrary commands.
- author_io_controls.py copies exact V0 bytes and sentinel and constructs fresh-open
  identifiers by the declared initial bootstrap ordering. It does not run a codec.
- FOCUS_CASES,PROTOCOL,OBSERVATION_SCHEMA and supported/refused/ownership/native tables
  are direct human-readable original literals. The focus inline full states are the
  Sp25/UndoS1 payloads with only retained preset changed to literal Z.25; all other
  values are copied exactly. The text/focus rules are fixed independently of I2 output.
- verify_expectations.py checks data references,lengths,typed ID uniqueness,full edge
  coverage,scope/layout consistency and strictly older rollback links. It calls no
  geometry/edit kernel. Pure verification does NOT prove the candidate accepts any
  case. STRUCTURAL_VERIFICATION is the preserved pre-IO pass; the FINAL file covers
  all current graphs/IDs/states. checkpoints/verify_pass1.py preserves that first script.

Original literal files are never overwritten by an authoring script: writers use
exclusive creation. Run them only in a fresh disposable copy preserving the frozen
old inputs; never rerun on the delivered expectation paths. Current files are the
review target. COMPLETE_INDEX is authoritative; earlier GRAPH_INDEX/CONTROL_COUNTS
retain their first-pass counts and are not presented as the complete final inventory.
Entry tables are disjoint and combined; rollback bindings extend only FreshReopen.

## Full data comparison

References always resolve ENTIRE Scene graphs and typed tables before comparison:
vertices and oriented faces/storage order; all face labels/materials/UV fields;
all attribute definitions/presence/values/assignment numbers,sets and zero-wall flags;
item transforms/hierarchy/import/workplane; ordered component selection; scope,
layout and explicit logical order; pre-Begin/begun roles/config/frame/current D;
entire chronological journal and cursor; retained preset and rollback ownership.
No counts-only,candidate-vs-candidate,nearest-coordinate or equal-valued ID matching.

The next_id field inside an old ID fixture is CONSTRUCTION metadata. It is not part
of IdentityScene and cannot restore a bank during Undo. Actual scalar bank values are
explicit in each state; e.g UndoS0 restores old IDs but keeps next83. Source/begun
snapshot identity comparisons exclude only that construction mark and instead compare
all real identity fields plus exact separate layout. Publication/request/stage/geometry
allocation never rewind. Raw unpredictable process/epoch are bound once to D0;foreign
D1 must be distinct. No raw item/generation/ID discrepancy may be normalized away.

Core step defaults in OBSERVATION_SCHEMA are explicit: accepted semantic action
publication+1/request+1,unless a row overrides. Ticket issuance only request+1. Refusal
keeps publication/request and complete accepted data unchanged after declared setup;
only explicitly listed fault seams burn reservations. New I2 budget preflight is a
routine engineering control within atomic refusal,not a Modo rule: check pub/request/
stage/32ID capacity before reservation and recheck publication eligibility at commit.
Legacy I1 allocation-exhaustion controls retain their original expectations unchanged.

Numeric Apply remains a separate lifecycle,no I2 stage allocation and one closed
entry per substantive operation. Its activation frame retention is an explicit
current-source compatibility observation,not a new Modo frame claim. Field Configure
updates retained preset;pointer Move does not until Drop;history does not rewind global
preferences. First Begin resets current extent0 while preserving its pre-Begin config.

All runtime/native/filesystem results are Not run. Published-data correctness,weak
reclamation,real I/O failures and actual native events require the later reviewed
implementation phase. Required supported refusal is failure;known unsupported refusal
is only a refusal result,not matching reference behavior. No final backend/DTO/API/
format/toolkit or performance claim follows from this preparation.
